01 — Topology

One entrypoint, one service — now with two databases behind it

Traefik is still the only thing exposed on the host, still routing to event-service by Docker labels. What changed this phase: event-service now writes to Postgres and MongoDB — relational event/venue/performer data in one, seat-map documents in the other. Redis, Elasticsearch, and Kafka are still provisioned but idle.

02 — Auth flow

Same token, two outcomes — now on a real write route

This is the actual sequence from the walkthrough above, now run against POST /events instead of the Phase 0 demo route: alice (role user) gets turned away; bob (roles user+organizer) gets through and creates an event. Role alone isn't the whole story this phase — see the ownership note below the diagram.

Role alone stops here — it doesn't answer "whose event is this?" That's a second, explicit check in EventManager: on PATCH/DELETE /events/{id}, the stored organizer_id is compared against the caller's JWT subject before any mutation. Verified live: carol (organizer role, different subject) → 403 on both bob's event; bob → 200/204 on his own.

03 — What's proven vs. not yet built

proven, live, this phase

  • ✓ gateway routes by Docker labels, no manual config
  • ✓ real Postgres and MongoDB round-trips on /healthz
  • ✓ Keycloak-issued JWT validated end-to-end (sig/iss/aud/exp)
  • ✓ role claim gates a route (403 vs 201, same code path)
  • ✓ ownership scoping — organizer role is necessary but not sufficient
  • ✓ events/venues/performers in Postgres via Alembic-managed schema
  • ✓ seat-map documents in MongoDB, fetched by event ID
  • ✓ public read APIs: list (paged, sorted), detail, seat map, venue

  • – nothing deployed to AWS (Phase 10)

04 — Reproduce this yourself

Every command below is real — this is exactly what was run to trace the diagrams above. Takes about a minute.

# from repo root
make up                                    # boots all 9 containers
make seed                                  # baseline venues/performers/events + one seat map

# public read — hits real postgres, paged + sorted
curl "localhost/events?limit=2&sort_order=desc"
{"items":[...], "total":3, "limit":2, "offset":0}   200

# alice: user only — cannot create
TOKEN=$(./get-token.sh alice)
curl -X POST localhost/events -H "Authorization: Bearer $TOKEN" ...
{"detail":"Requires role: organizer"}              403

# bob: user + organizer — creates an event he owns
TOKEN=$(./get-token.sh bob)
curl -X POST localhost/events -H "Authorization: Bearer $TOKEN" ...
{"id":"...", "organizer_id":"<bob's sub>", ...}  201

# carol: organizer, but not the owner — blocked from bob's event
TOKEN=$(./get-token.sh carol)
curl -X PATCH localhost/events/<bob's event id> -H "Authorization: Bearer $TOKEN" ...
{"detail":"not the owning organizer"}             403

make down                                  # tear down
